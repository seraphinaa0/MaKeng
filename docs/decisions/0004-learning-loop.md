# ADR 0004 — Learning loop in the browser demo

Phase 4 continues the user-authorized browser-only demo. Add `/progress` for activity, Reading accuracy by type, observed error categories, deterministic recommendations and a mistake retry queue. The local SQLite mode remains Phase 1–2; no new cloud backend or AI credentials are assumed.

Compute statistics from complete submitted attempt snapshots, never paginated history, unfinished attempts or model bands. Writing shows submission/word counts only: mock evaluations cannot measure criterion trends. Reading shows raw correct/total counts, not IELTS bands. Date filters use rolling 7/30-day intervals ending at the current instant; display timestamps in the browser's locale. Trend compares the latest three attempts containing a type with the preceding three, only when all six exist in the selected interval. Counts and repeated-content limitations are visible; this is descriptive practice data, not calibrated ability estimation.

Classify only observable mismatches: blank, completion word-limit violation, MCQ mismatch, TFNG mismatch, completion mismatch. Do not infer vocabulary, grammar or psychological causes. Each mistake references its immutable attempt and question, and review retries cannot alter the original score. Correct retries mark an occurrence reviewed; users can reopen it. New mistakes on later attempts have separate identities.

Recommendation priorities: continue an unfinished attempt, review pending mistakes in the highest observed error-rate type, then practice a catalog set containing that type (prefer less-practised versions, then self-published content, then stable ID order). Every recommendation explains its inputs. Users can disable, dismiss and restore suggestions; these preferences persist. Preview sets remain labelled, and unpublished drafts are never candidates.

Keep the existing storage key to preserve access. Upgrade the version-1 state to version 2 in memory, add `learning` with default preferences and revision, and persist it atomically on the next successful mutation. Validate before replacement; never erase legacy state on errors. Web Locks and a shared learning revision prevent lost updates across tabs. Session deletion removes progress/preferences/reviews, and the existing JSON export includes them. Old open builds must reload after a v2 write. This does not migrate SQLite history, provide cloud sync or claim secure testing.
