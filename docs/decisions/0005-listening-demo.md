# ADR 0005 — Private browser Listening slice

The user requested Phase 5 after choosing build/self-review before deployment. Work stays on a local branch; neither main nor Vercel is updated. The managed workspace can review production builds in Chromium, but cannot claim a review on the user's Windows machine.

Add `/listening` in browser-demo mode. Store imported audio Blobs, immutable content, consent metadata and attempts together in IndexedDB transactions, separate from existing v2 localStorage history. No audio/transcript is sent to a server or AI provider. Use an original short synthesized sample and its pre-authored cue times for a fixture transcriber; require matching audio hash to prevent applying fixture text to arbitrary uploads. For user audio support manual WebVTT transcription via the same typed STT interface. Real STT, private cloud buckets, signed URLs, provider consent and human transcript benchmarks remain future integrations; do not label the manual/fixture flow as speech recognition.

Limit accepted audio to browser-decodable WAV, MP3, Ogg, WebM and MP4, 20 MiB and 30 minutes; check MIME, file size and decoded duration. VTT supports plain timestamped cues only, rejects HTML/markup, duplicate/overlapping/out-of-order cues and ranges outside the audio. Build sentence-completion questions manually with exact cue/quote evidence, word limits and explicit local review before creating user practice content. The original bundled sample remains a labelled preview; private audio never goes into public assets.

Practice uses raw question scoring, revision-checked autosave, immutable submission, confirmation of blanks, section navigation and timed evidence playback after submission. Retries/resume/history persist locally. Answer keys reside in the browser, so this is not secure testing. Listening results are separate from the Reading-only Phase 4 analytics.

Default retention is 7 days; options are 1/7/30. Expired audio and its content/attempts are removed atomically on the next Listening access, not by a background timer while the browser is closed. Explicit deletion removes the Blob, transcript and all attempts; global demo deletion also clears IndexedDB. Revoke object URLs and reload active views on cross-tab deletion. Export includes per-lesson JSON and separate audio download; the existing localStorage JSON backup does not contain audio. Device copies/downloads cannot be recalled.

Do not change or erase existing Writing/Reading history. Test persistence, timestamp boundaries, scoring, retention, corrupt/blocked storage, deletion and cross-tab stale writes; validate the production UI on desktop/mobile. Real STT quality and production auth/privacy exit criteria remain open.

## Continuation — portable backup restore

Add an explicit local restore flow accepting the exported JSON plus the matching audio. New exports use a strict `kind: makeng-listening-backup`, `schemaVersion: 1`, UTC `exportedAt` envelope around the existing lesson schema. Continue accepting the earlier bare lesson JSON. Reject unknown versions/fields, files over 10 MiB JSON or 20 MiB audio, invalid evidence/history/publication, and mismatched audio size/SHA-256/decoded timestamps. A backup's provenance is a local claim, not authenticated teacher approval.

Show the lesson title and submitted/in-progress counts before restore. Require renewed local storage/usage consent and a new 1/7/30-day retention period. Restoring expired backups is allowed after this explicit renewal. Create a new lesson and new attempt IDs, retaining immutable content, answers, status, revision and original attempt dates. This prevents a deleted tab's stale attempt from addressing the restored copy. Do not merge or overwrite existing lessons; reject an identical content/history snapshot inside the insertion transaction, excluding volatile IDs and retention. Apply existing library/count/byte limits atomically. Do not alter IndexedDB's existing store/version or Writing/Reading data.

Restore holds the Listening Web Lock from audio validation through insertion. A global deletion requested during that operation waits, then clears the restored audio; the operation cannot re-create audio after that deletion finishes. Restore never invokes STT or sends files to a server. Input files stay available on error; validation/duplicate/quota errors never report success. Export and restore are personal backup tools, not secure testing or import of unreviewed published content.
